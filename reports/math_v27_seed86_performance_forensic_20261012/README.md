# V2.7 seed86 实验表现审计（零 API，2026-10-12）

结论：本轮执行有效，观察到 Optimize Vote 的净提升，但不是科学收敛，也未建立独立泛化或组件因果效果。收益以保留损失为代价；主要可见问题是高比例的 NO_SAFE_EDIT、低分辨率局部指标、Probe 到 Full 的 Vote 回退，以及昂贵的 Gradient 格式重试。没有发现局部排序、Probe 排序或 Full 赢家选择偏离冻结规则。

本报告复查的是已完成的 `math_v27_seed86_precluster_continuation_v1`，执行源 `a8985eef7f15f82ae29bf8000cccf12b0ad39b2a`，结果发布提交 `00f235a2861ce413f09ab7fb8d12a2bf5dfadf3b`。不改写[原执行报告](../math_v27_seed86_continuation_execution_20261012/README.md)。原始轨迹、问题、答案、prompt 与响应均未公开。本次没有 API、Validation/Test 原始数据读取、参数修改或续跑；本次发布仅包含文字报告与脱敏统计，不包含新增图形。

## 3. 漏斗：主要损失发生在哪里

| 环节 | 数量 | 对应解释 |
|---|---:|---|
| Reflection 生成槽 | 300 | 50 × 6；不是 300 个可评估编辑 |
| NO_SAFE_EDIT | 190（63.33%） | 合法无候选输出，不是格式错误 |
| CONTRACT_INVALID | 34（11.33%） | 多种检查可能同时失败 |
| 局部可评估编辑 | 76（25.33%） | 76 次都推进临时父 prompt |
| 导出、获得 Probe | 70 | 六个编辑受 top-4 上限截掉 |
| 已见修复失败 | 33 | 未达到至少一条已分配 0→1 修复 |
| Probe 通过 | 37 | 本次无独立 Probe catastrophe 拒绝 |
| 获得 Full | 31 | 另六个受每机会 top-2 上限截掉 |
| Full 通过 | 6 个候选、5 次机会 | 第 7 次机会有两个合格候选 |
| 选中赢家 / Shadow 通过 / Commit | 5 / 5 / 5 | 本次 Shadow 没有淘汰赢家 |

16/50 次机会六轮全是 NO_SAFE_EDIT，没有任何可评估编辑。34 个无效输出包含 14 次 block/length 检查、5 次结构检查、12 次重复、12 次 parent no-op、3 次私有解答/响应复制；这些计数有重叠，不可求和作为输出总数。

25 个 Full 拒绝中，23 个发生 Vote 回退，17 个没有 target-or-team 正进展，2 个低于初始成员能力地板；三项重叠。其中八个候选目标成员正确数提高，但团队 Vote 下降。这说明“提高单成员正确数”与“保住团队正确答案”在本次输出上发生实际冲突，不能只优化前者。

六个 Probe 合格但未获 Full 的候选没有完整评估，无法推断它们更好或更坏，也无法认定 top-2 导致错失 Full 赢家。

## 4. 局部指标、排名与旧遗留问题

76 个局部编辑按相对机会根父 prompt 的 SearchValidation（三题）净变化分为：7 正、54 中性、15 负。七个正收益编辑全部导出，六个未导出编辑均非正收益。局部 top-4、Probe top-2、Full 赢家规则各逐次复算了 50 个机会，均符合冻结规则。

七个局部正收益导出候选中：四个未完成已见修复，两个被 Full 拒绝，一个通过并 Commit。五次 Commit 中只有一次局部 SearchValidation 为正；第 27 次甚至局部 −2，却 Full Vote +2。此处的“局部”是 SearchValidation，不能推广为所有 Mutation/Probe 信号均无效。它支持局部指标分辨率及覆盖代表性有限的诊断，不建立 selection 的因果失败结论。

`local_survival_updates = 0` 是该搜索实现固定为零的计数，不能解释为“临时父 prompt 没有更新”：76 次局部评估全部推进，其中 70 次相对即时局部父状态中性或负向，均属冻结的 evaluated-parent 行为。`admissible=false` 是中立候选记录中的占位字段；当前 transition 使用 promoted、Full 和实测门禁，不能据此误判五次 Commit 非法。

Gradient 共 1618 个错误例，1472 ACTIONABLE（90.98%）、142 三次耗尽、4 UNCERTAIN。2441 个生成 draw 中 965 被拒绝（39.53%）；426 个错误例在重试后恢复。ACTIONABLE 仅表示通过契约与内容守卫，不是数学诊断被证实正确。

前 27 次机会消耗 10,768,035 Token，后 23 次消耗 **9,255,200（46.22%）**、3839 个请求，后段没有新 Commit。后段仍有 34 个局部编辑、31 个导出候选、14 个 Full，全部 Full 被拒；平台期并非搜索停止生成编辑。格式/契约无效比例由前段 12/162 升至后段 22/138，NO_SAFE_EDIT 比例反而由 108/162 降至 82/138，不支持把平台期单独归因于更多无编辑响应。

此为事后成本分解，不能反向更改冻结停止规则，或认定继续一定无收益。每次机会平均约 400,465 Token；“每题净 Vote 提升约 301 万累计 Token”只是粗粒度描述，不是泛化成本或可外推价格。

## 6. 终态剩余问题和下一步优先级

最终 25 道 Vote 错题中，19 道五成员全错，6 道已有正确覆盖但 plurality 未选中（其中四道仅一票正确，两道两票正确）。Oracle 与 Vote 的差仍为六题，和初始相同，但题目身份及中间状态会变化。当前残余错误中 76% 缺少任何正确覆盖，24% 属覆盖未转成 Vote；不能再把 plurality conversion 视为唯一主要瓶颈。

1. 先为最终团队与冻结初始团队做单独预注册、授权的 paired Validation，使用规定的相同请求实现复用。它回答收益是否离开自适应支持仍保留；本次未执行，也未产生授权。
2. 零 API 继续核查 190 次 NO_SAFE_EDIT 的语义理由、707 次超限的字段结构及候选 parent→child 的具体修复泛化，区分真实无可执行编辑、保守拒绝和契约表述困难；不能通过放松守卫把失败隐藏掉。
3. 若开发新 Layer1，优先测试对 preservation 与团队 Vote 风险更有代表性的局部证据，而不是直接增加 generation。七个局部正收益全导出，当前证据不支持先归咎 top-4 实现；六个未获 Full 的合格 Probe 的机会成本仍未识别。
4. 更改诊断输入、重复证据表示、长度引导或停止规则均应有新版本及冻结对照。保留直接可读的完整数学证据，不恢复数字切片任务。继续同一支持上的搜索不能替代独立评价。

以上是研究优先级，不是方法变更或新运行授权。单一 adaptive run、选择后的五个 Commit、三题 SearchValidation、六题 Probe、四十题 Shadow 及没有 repeated Solver realization 的事实，均限制统计和因果解释。

# Post-refactor GEPA proposal-contract audit

Primary diagnosis: `PROPOSER_OBJECT_SCOPE_MISMATCH`. The completed real-provider canary generated four changed proposals, but all four included a role-style preamble and an output section. Three exceeded the frozen 3000-character limit; two also triggered formatting-interface checks, one of those mentioning the forbidden final-answer marker. All four were correctly rejected **before candidate Solver evaluation**. This is evidence of component-scope noncompliance, not evidence that GEPA local optimization or local-to-team transfer failed.

| 1 | 3130 | `over_length` | decision procedure + extra shell | Removing detected role/output shell leaves 2650 characters. |
| 2 | 3388 | `over_length`, `copied_solver_interface` | output-contract contaminated | Removing detected shell leaves 2907 characters. The recorded interface category was caused by a generated formatting directive, not proven verbatim copying. |

| 4 | 2996 | `forbidden_final_answer_marker`, `copied_solver_interface` | output-contract contaminated | Not over length; generated formatting language and a final-answer marker are forbidden. |

The shell segmentation is diagnostic, not a substitute validator: it uses heading boundaries in the extracted text. The production validator intentionally checks the full candidate. No candidate was truncated, rewritten, or admitted by this audit.

The `copied_solver_interface` name is a contract-check category, **not** proof that literal immutable interface bytes were copied from an input. For proposals 2 and 4, the recoverable spans are generic output-format directives. The persisted parent component contained only a generic role preamble and reasoning instruction, not the immutable answer interface. The executed adapter's side-information path removes terminal-answer lines and output-format commentary from Solver traces. Because the four exact Reflection requests and raw responses were not persisted, the source of the generated formatting language cannot be identified uniquely among model extrapolation, task context, or omitted input details. We do not attribute it to Layer2 evidence or parent-shell copying without that evidence.

The executed project template already asked for reasoning-only text and prohibited answer-format instructions, but called the parent a complete procedure while that parent began with role wording. The narrow fix clarifies that the mutable object is exactly `decision_procedure`, and that the model must not produce a system prompt, role/persona preamble, output section, or immutable interface. It does **not** alter the frozen 3000-character threshold, normalization, validator, GEPA search core, Layer2 controller, reflection budget, or any API access policy. Classification: `SCIENTIFIC_METHOD_CHANGED=NO`; `INTERFACE_COMPLIANCE_FIX=YES`; `SCIENTIFIC_INTERFACE_CHANGED=NO`.

The most recent pre-refactor local GEPA acceptance pilot had 11/32 contract-valid proposals under the same component, project template, validator, length rule, and pinned GEPA extraction. Source diff identifies no post-refactor proposal-shape adapter regression. However, its local evidence and stochastic provider samples differ; this is **not** a performance comparison. The eight golden semantic traces tested deterministic orchestration, not real-model proposal shape.

Evidence limitation: official GEPA persisted the four **already-extracted** proposal texts and project callback hashes. The raw Reflection response bytes and exact rendered request bytes were not retained. Their hashes and raw-response extraction replay are therefore `NOT_RECOVERABLE_ZERO_API`. Replaying the four extracted texts through current normalization/contract validation reproduces all four proposal hashes, failed-check sets, primary rejection categories and reject decisions. The label “stored proposal replay PASS” refers only to that recoverable stage.

The immutable completed run consumed 104 successful provider calls (100 initialization Solver, 4 Reflection), 23,332 input tokens, 9,545 output tokens, 32,877 total tokens; provider failures, candidate Solver calls, local deltas, Validation50 and Test50 were all zero. This cost remains assigned to the completed run, never a later canary.

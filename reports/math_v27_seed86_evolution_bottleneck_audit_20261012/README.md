# V2.7 Seed86 持续演化与有用互补性瓶颈审计

2026-10-12。只读既有代码和封存证据，零 API；不改算法、协议、历史报告或实验结果，不启动新实验，不新增图形。成员编号均为 1–5。本文是下一轮设计的诊断依据，不是新方法规范或运行授权。

## 1. 核心判断与证据等级

**低 Commit 转化率有三个不同来源：16 次机会没有产生可评估编辑，11 次有编辑却没有进入 Full，18 次进入 Full 但没有合格候选；另外 5 次成功 Commit。** 把它们全部归结为“门禁过严”或“模型不会生成”都与证据不符。

最值得优先验证的是：**局部证据没有充分呈现团队的关键保留能力，目标成员净增也不是团队收益的充分代理；Full 的失败经验又没有稳定进入下一次编辑的实际输入。** 序列化失败、重复诊断与追加式 prompt 的容量压力扩大了搜索成本。WHO 的最优性和 Solver 随机性的贡献仍缺少对照。

三个已更新成员具有可见的条件互补性，不能将“仅更新 3/5”本身定义为失败。应追求有用、可保留的团队变化，而不是更多 Commit、所有成员都更新或更大 disagreement。

## 2. 证据范围和方法

审计对象为 `math_v27_seed86_precluster_continuation_v1`，冻结源 `a8985eef7f15f82ae29bf8000cccf12b0ad39b2a`。既有结果发布于 `00f235a2861ce413f09ab7fb8d12a2bf5dfadf3b`；本次基于 `ac37919629f053a444a37dfd8eb49b18a893a935` 的代码与已封存证据。11 个相关生产源文件与冻结源逐字节比对，在只统一 CRLF/LF 后一致。新报告不反向决定科学方法。

沿用[上一份 Performance Forensic Report](../math_v27_seed86_performance_forensic_20261012/README.md)的执行完整性结论，新增分析聚焦机制。逐次读取 50 个机会的父/子团队、候选 lineage、实际角色输入、Memory bank/序列化视图及封存缓存；重建 31 个 Full 的 4,650 个候选—题目关系。每个 Full 的 Vote 新增/丢失计数与记录一致；Mutation、SearchValidation、Probe 的修复/丢失/invalid 集合与 Full 限制到同一题目后完全相等，31 个 Probe Vote 子集也相等。必要的答案等价检查使用冻结的本地数学 verifier，不调用模型。

人工读取 16 个事件、14 道不同题目的完整可见书面解题响应和已有参考解，覆盖五次 Commit 的全部 7 次 Vote 丢失和 5 次独有覆盖丢失，另检查反复受损的 Full 题目。书面响应不是模型隐藏推理。原问题、具体答案、prompt、原始响应、供应商信息和私有主机路径不公开。

本次只分析 Optimize 和已有模型实现。Validation/Test 原始数据读取为 0，API 为 0。既有正式实验是有效的资源截断执行，50 次上限不等于科学收敛。下面所有重复事件数都不能当作独立题目或独立试验数。

## 3. 从 Gradient 到 Commit：失败落在哪里

| 机会的终止位置（互斥） | 机会数 | 能支持的解释 |
|---|---:|---|
| 六轮全 NO_SAFE_EDIT、没有可评估编辑 | 16 | 编辑产出瓶颈；没有文本理由，不能判断弃权原因 |
| 有局部编辑，但没有 Full | 11 | 导出候选未满足已见分配修复要求；不是 Full 门禁造成 |
| 有 Full，但无 Full 合格候选 | 18 | 实际完整表现不符合冻结要求；需要分析候选退化与收益结构 |
| Commit | 5 | 五个选中赢家均通过 Shadow，本次不是 Shadow 瓶颈 |

机会层转化为 50 → 34（有编辑）→ 23（有 Full）→ 5（Commit）。以下是另一种单位，不能和机会数混用：300 个 Reflection 槽中 190 NO_SAFE_EDIT、34 契约无效、76 可评估编辑；70 个导出候选得到 Probe，33 个未完成已分配修复，37 个 Probe 合格，31 个得到 Full，6 个 Full 合格候选分布于 5 次机会，最终 5 个 Commit。第 7 次机会有两个 Full 合格候选。

Gradient 对 1,618 个错误例生成 2,441 个 draw，得到 1,472 ACTIONABLE、142 次耗尽、4 UNCERTAIN。所有机会都有可选 Pattern，没有整体 Gradient/Pattern 耗尽导致机会无法开始的情况。ACTIONABLE 是契约与内容守卫结果，**不是诊断数学正确、修复可实现或具有团队价值的验证**。

Full 拒绝的 25 个候选中，23 个 Vote 回退，17 个缺乏目标或团队正进展，2 个跌破初始成员地板，三者重叠；8 个属于目标正增但 Vote 负增。冻结门禁保护了已部署 Vote，现有 Full 不支持直接放松门禁。Oracle 非回退不是当前门禁，第 27 次 Commit 的 Oracle −1 合规，但仍有科研上的保留代价。

Local export、Probe top-2 和 Full winner 规则已在前次报告逐次复算，符合冻结规则。7 个局部 SearchValidation 正增益编辑全部导出，6 个未导出编辑都非正增益；没有发现排序偷偷剪掉已观察局部正增益。33 个已见修复失败候选和 6 个 Probe 合格未晋级候选缺少 Full，不能知道其中是否存在遗漏赢家。实现合规、评价信息不够和未知候选质量要分开。

## 4. 局部证据为什么没能预测团队收益

### 4.1 采样机制和信息流

`search/selected_evidence.py::compose_disjoint_evidence` 优先从选中 Pattern 的错误支持取最多三道 Mutation，不足时随机补齐；SearchValidation 三道、Probe 六道从剩余 Optimize 随机取，三组互斥。**没有按初始正确、独有覆盖、Vote 关键性或最近 Full 反复丢失设置保留配额。** 不能把另一个 `rotated_correct` 工具当成当前生产图已生效的锚点。

50 个机会中，Mutation 有 39 次完全没有目标原正确题；49 次没有 dropout-pivotal 原正确题。SearchValidation、Probe 无这种题的次数分别为 47、45。若扩大到 margin ≤2 的 Vote 风险题，三组仍分别有 49、40、35 次完全未覆盖。这里 dropout-pivotal 指移除目标正确票即使原 Vote 失去严格胜出（margin=1）；margin=2 还要看目标新的错误票是否加入另一错误类，不能把所有 margin=2 都称为必然 pivotal。

`binary_runtime.py::BinaryEvidenceSource.for_member` 的丰富证据本来包含团队正确、margin、disagreement、mutation_sensitive 等信号；当前局部抽样没有优先利用这些保留特征。最新成功 Commit 的修复/丢失题会形成 focus/anchor 信号，但不等于累计所有 Full 拒绝的危险题都被保留下来、被抽样或被模型看到。

`bounded_layer1.py::build_optimizer_context` 给 Reflection 完整可读的当前 Mutation 题目、目标普通 Solver 响应、答案参考、当前 prompt、选中 Pattern 和 Memory。300 个实际 Reflection 输入的 900 个 Mutation 观察均含直接可读的响应文本，不要求模型执行数字切片。与此同时，Reflection 不直接读取同伴输出、Vote margin、原始 SearchValidation/Probe 题目或 worked reference solution；SearchValidation 可经 Memory 的计数反馈进入下一代，不能说完全没有反馈。完整数学参考轨迹、细致 observed_failure/diagnosis/expected_effect 位于上游 Gradient；传给 Cluster 的主要是 reusable_correction，Reflection 收到进一步广义化的 Pattern。**现有完整文本已恢复，但角色任务所需的团队保留语境和诊断细节仍有损失空间。**

这是代码的信息拓扑，不是模型实际理解能力的因果测量。优先补足必要信息，不以删掉题目、Solver 轨迹或参考依据换取成本下降。

### 4.2 相关性与覆盖

以下仅使用已晋级 Full 的 31 个候选，均有筛选、同父状态聚类和大量 ties。表中的相关系数是描述性结果，不是全候选泛化性能，不做独立样本显著性推断。

| 局部信号 | 与 Full 目标净增的 Spearman | 与 Full Vote 净增的 Spearman |
|---|---|---|
| Mutation 目标净增 | 0.310 | 0.170 |
| SearchValidation 目标净增 | 0.265 | -0.136 |
| Probe 目标净增 | 0.086 | -0.099 |
| Probe Vote 净增 | 0.141 | -0.036 |
| 已分配修复数 | 0.239 | 0.172 |

Probe Vote 在这些候选中 −1 有 2 个、0 有 27 个、+1 有 2 个。两个 Probe Vote 正增的候选，Full Vote 分别为 0、−2。**三个实际提高 Full Vote 的候选，Probe Vote 和 SearchValidation 均无正增益。** 因此直接要求局部或 Probe 正增，会丢弃本次全部三个 Vote 提升赢家。

31 个 Full 累计 89 次 Vote 丢失，只涉及 19 道不同题；Mutation、SearchValidation、Probe 分别覆盖其中 1、2、2 次，三组互斥，所以合计 5/89。集合与 Full 子集完全一致，说明在这些固定实现上是面板没看见，大体上不是“同一子集重新生成后随机变坏”或算错评价。不同 prompt 之间新的 Solver 实现变化仍无法识别。

局部 SearchValidation 的 76 个编辑为 7 正、54 中性、15 负。即使量尺统计无误，三题目标净增也很难表达少数 Vote 关键能力、异质错误类和跨题保留风险。增加均匀样本、增加团队风险特征、改变 selection metric 是不同干预，下一轮应分别检验。

## 5. 候选带来的能力到底是不是团队需要的能力

### 5.1 逐题区分独有覆盖、正确冗余和关键票

31 个 Full 累计目标修复 216 次、丢失 246 次；其中修复 48 次是此前无人正确的独有覆盖，168 次已有其他正确成员。**115/216 次修复发生在原团队 Vote 已正确的题目上**；40 次真正翻正 Vote，另 61 次修复后 Vote 仍错误。正确冗余能增强 margin 或支持后续演化，不能一概视作无价值，但它不是当前 Vote 净增。

246 次目标丢失中，28 次丢失唯一正确成员，218 次仍有别的正确成员。后者并不安全：84 次目标正确→错误实际打破 Vote，其中 68 次父 margin=1，16 次父 margin=2；新的错误票和同伴错误答案聚类决定了后者的结果。

另有 5 次 Vote 丢失、3 次 Vote 新增，目标正确性完全没变，来自错误答案类合并/拆分。这说明只看 binary member Accuracy 还会漏掉少量真实 plurality 变化。本报告使用冻结数学等价关系重建，而不是把答案字符串不同直接当成独立票。

### 5.3 为什么目标净增经常伴随 Vote 下降

八个目标正增/Vote 负增候选并不矛盾：修复了团队已有多数正确票的题，只增加正确冗余；丢失少数目标关键正确票，却改变严格 plurality 赢家。独有新增有时仍只形成一票正确，不能立刻打破错误多数。候选应同时呈现所需修复、关键保留和错误票类变化，不能只以 target net 给出“改善”的总标签。

Vote 丢失的粗类型为 Intermediate Algebra 42、Precalculus 23、Geometry 13、Counting & Probability 6、Number Theory 5。三个高频题分别重复出现 13、10、10 次损失，占 33/89；前四个占 42/89。Full 已经多次暴露同一危险能力，但当前面板及简略 Memory 未稳定把这些详细失败约束带回后续生成。

## 6. 只有三个成员更新，是否缺少有用互补性

保持成员 1、4 不变，对成员 2、3、5 分别选择封存的初始或最终输出，形成八个混合团队；只重新聚合既有响应，不调用 Solver、不执行替代搜索。初始和最终两端与正式记录一致。

|---|---|---|
| 无 | 118 | 124 |
| 5 | 119 | 129 |
| 3 | 118 | 128 |
| 3,5 | 121 | 130 |
| 2 | 120 | 129 |

成员 3 单独换入时 Vote 仍为 118，但在成员 2、5 已最终更新的团队中贡献两题：最终团队撤回成员 3 为 123/131；撤回成员 2 为 121/130；撤回成员 5 为 119/129。三个条件边际 Vote 为 2、4、6，存在重叠，不能相加成总收益。**已有三个更新之间存在有用条件互补性；第 11 次即时 Vote 持平的 Commit 不能只按即时 Vote 判断。**

这些是封存输出的确定性替换诊断，不是 prompt/optimizer 因果消融：没有重采样，也没有重新运行其他搜索顺序。替换出来的团队从未实际执行为实验终态，不列为新实验成绩。

最终独有正确数按成员为 0、2、0、1、2；dropout-pivotal 数为 1、5、6、3、6。未更新成员 4 仍保有一个独有正确、三个关键正确票；强求五个成员都更新可能损伤团队。成员 3 没有独有正确仍可以对 Vote 有用，说明独有覆盖也不能独自作为互补性的指标。这里没有建立数学 specialization 语义或跨分布泛化。

### 6.2 Responsibility 及机会分配

`policies.py::TargetPolicyV1` 的分数是 `max(4D, 2N, C) / (1 + failure_count)`，正分数最高者胜出、同分取低成员编号；全部为零才随机。本次 50 次选择逐次复算一致。任一无 Commit 增加所选成员的 failure_count，Commit 将该成员清零；它不区分生成失败、局部失败、Full 退化或花费，也不是已学得的期望团队收益模型。

| 成员 | 机会 | NO_SAFE / 生成槽 | 可评估编辑 | 局部正增益 | Full / 通过 | Commit |
|---|---|---|---|---|---|---|
| 1 | 8 | 46 / 48 | 2 | 0 | 1 / 0 | 0 |
| 2 | 9 | 41 / 54 | 13 | 0 | 6 / 1 | 1 |
| 3 | 10 | 24 / 60 | 28 | 4 | 13 / 1 | 1 |
| 4 | 7 | 38 / 42 | 4 | 2 | 1 / 0 | 0 |
| 5 | 16 | 41 / 96 | 29 | 1 | 10 / 4 | 3 |

成员 1、4 没有饥饿：分别有 8、7 次机会，但 48/42 个生成槽中 46/38 次 NO_SAFE_EDIT，各只有一个 Full；那个 Full 分别 Vote −1、−3。成员 5 有 16 次机会、3 次 Commit，贡献本次净 Vote 的 5/7，集中有已实现收益依据。另一方面失败计数归零后成员 3 一次、成员 5 三次立即再次被选，存在规则确定的成功后折扣重置反馈，但无证据证明该反馈不当。

WHO 所选责任 lane 为 direct_flip 8、near_margin 14、coverage 28 次。初始 raw 分数为 16、19、15、16、20，最终为 13、13、13、13、15；第 50 次前失败计数为 8、8、7、7、9，分数为 1.444、1.444、1.625、1.625、1.500，成员 3 以同分规则胜出。后 23 次分配为 4、3、4、3、9。并非只在同一成员无限重试。

局部容易被修好的错误，与团队需要的新能力或应保留的关键票并不等价。当前调度至少缺少“该成员的这一类失败能否被编辑修好、成本多少”的阶段信息；这是可检验假设，不是调度错误结论。没有在同一父团队上生成未选成员的等预算候选，无法比较它们的真实机会质量或认定更均衡调度会更好。

## 7. Prompt 和 Memory 是如何演化的

### 7.1 追加文本不是行为保留

76 个合法编辑中 74 个改 Strategy、2 个改 Answer、0 个改 Role；66 个保留即时父块完整前缀，74 个增长长度。五次 Commit 全部改 Strategy，局部链深度为 1、2、4、4、2。成员 2、3 的最终 prompt 为 617、764 字符，成员 5 为 313 → 972 → 1790 → 2492；五次增量为 304、659、451、818、702 字符。

代码允许三块均改；当前示例中的 Strategy 目标可能提供生成偏向，但没有强制禁止其他块的证据，也没有示例消融。不要把观察到的修改集中误当成编辑接口封锁。

合法局部编辑即使中性或负向也会推进临时父状态，top-4 导出按 SearchValidation 净增、broken、Mutation 净增和较早 generation 排序。故后续生成可能继承已累积的不良编辑。该行为符合冻结方法；没有替代 parent-survival 对照，无法估计其净影响。

### 7.2 bank 有 Full 不代表模型收到了 Full

精确核对 300 个 Reflection 的实际 Memory 输入，并将其与 bank 和预截断选择匹配：

| Memory 观察 | 次数 / 分母 | 解释 |
|---|---:|---|
| bank 已有本成员 Full | 240/300 | 可能用于反馈的机会 |
| 实际输入包含 Full | 113/240 | 其余 127 个没有送达 |
| 优先级没有选中已有 Full | 34/240 | 当前 local 的同 Pattern 精确匹配先于旧 Full |
| 选中了 Full，但字符限制删掉 | 93/240 | 送达的第二道瓶颈 |
| 实际 delivered edit 记录数 | 267 个一条、33 个零条 | 从未达到配置 top-3 的两条/三条 |
| 已有 shared risk / 实际送达 | 276 / 22 | 254 个输入未看到已有 shared 风险 |
| delivered Full 状态 | 109 FULL_REFUTED、4 COMMITTED | 正向成功经验很少出现在实际视图 |

`rolling_risk_memory.py::_read_evidence` 先排精确 Pattern/假设匹配，再优先 Full-refuted、按时间；最多私有三条/共享三条，总序列化限制 1200 字符，先删 shared，再删私有至一条，仍超限则删最后一条。Full 单记录可见长度为 740–876，中位 797；单独能放下，但加初始覆盖等视图可能超限。**不是每条 Full 绝对放不下，而是排序与整包预算组合导致真实丢弃。**

50 次选中 Pattern 的身份全部不同，跨机会首个 read 的精确 Pattern 命中为 0；同机会后续 150 次 read 可以命中新写入的局部记录。因此不能说 Memory 完全没有命中，也不能用 bank 存在证明跨机会重用有效。

成员私有成功记录不会直接成为另一成员的数学修复策略；共享的是概括风险。可见 Memory 主要是 scope、净增/损失等计数，不直接传递 Full 丢失题的具体机制、类型和关键票角色。重复危险题既然已经在 Optimize Full 中可见，未来版本可以研究其精确条件化反馈和完整送达，但不能在当前冻结实验里偷偷改输入。

这些是确定的信息送达缺口。负面记录占优是否使模型过度保守、精确文本 Pattern 身份是否造成重复学习、更多成功经验是否有益，仍需对照；不能从 109/4 比例直接推断模型心理或因果效果。

## 8. 搜索效率、格式问题与后 23 次平台期

### 8.1 NO_SAFE_EDIT 能解释什么

190 个 NO_SAFE_EDIT draw 花费 1,791,842 新 Token，约续跑总量的 8.95%。其中 131 个面对 Mutation 0/3 正确、19 个 1/3、20 个 2/3、20 个 3/3；76 个发生在此前已有合法局部编辑之后。部分弃权发生在已修完可见题之后，不能一律视为生成能力不足。

16 次六轮全 NO_SAFE_EDIT 的机会中，六次输入各自在同一机会内逐字节一致，没有 parent 或新评估反馈。合法输出只含决定字段，未提供拒绝理由；不能从空编辑还原模型究竟是没找到修复、怕破坏能力还是误读 Pattern。人工检查这 16 个选中 Pattern，包含较宽、混合机制的修复建议，但未建立可量化语义质量或共同失败原因。

24 次机会首轮 NO_SAFE_EDIT，其中 8 次后来仍产生编辑，**第 2、11 次最终 Commit**。据此“第一次 NO_SAFE 就退出”会损失已观察成功，六轮相同输入也不自动等于六次确定性重复（provider 输出仍可能变化）。后续若增加闭合拒绝原因，只能作为可审计自报信号，不当作原因真值。

### 8.2 Gradient 的契约摩擦具体是什么

965/2441 个 Gradient draw 被拒绝：707 个涉及字段超限、173 个非法 JSON 转义、54 个内容拒绝、10 个 JSON 语法、17 个截断、4 个键集合错误。一个 draw 可以多个字段超限，故超限字段总事件数 903 不能当成 903 个独立失败响应。

| 字段 | 超限事件 | 超出上限的中位字符 | 最大超出字符 |
|---|---:|---:|---:|
| diagnosis | 452 | 92 | 4827 |
| observed_failure | 303 | 85 | 3858 |
| reusable_correction | 98 | 44 | 1205 |
| expected_effect | 50 | 27.5 | 598 |

并非全部只差一两个字符。数学反斜杠写入 JSON 字符串时没有正确转义是 173 次转义拒绝的常见模式；这些是生成表示错误，不应通过放松解析器掩盖。存在字段/上限反馈：598 个收到超限反馈的下一 draw 有 313 个接受；150 个收到转义反馈的下一 draw 有 76 个接受。契约恢复帮助过一部分响应，但没有消除问题，且成功率不是数学诊断质量。

另外发现 12 个接受为 ACTIONABLE 的例子含 JSON 解码后的 C0 控制字符，其中 6 个出现在 reusable_correction；这是合法 JSON 转义与数学文字表示的边界问题。一个选中支持例有此情况，选中 generalized Pattern 和已部署 prompt 的相关控制字符均为 0。**确认字符存在，不宣称已经造成数学语义损坏或最终 prompt 污染。** 下一版可加入严格表示测试和更明确输出指引，不能自动替模型补写诊断。

续跑新 Gradient 成本 11,067,148，占新总 Token 的 55.27%；拒绝 draw 成本 4,506,179。输入占新总 Token 75.78%，所以真实效率问题不仅是输出长。不同 prompt/trajectory/ref 等必要信息不能随便删除。

### 8.3 重复诊断的量与解释

1,618 个逻辑错误诊断的首 draw，规范化完整 provider 请求只有 330 种，重复首输入 1,288 次（包含父实验导入前缀；授权域不同的 request identity 仍不同）。续跑 2,388 个物理 Gradient draw 有 1,042 种完整 request，1,346 次是在续跑已见完整请求上的再次生成，成本 6,228,336 Token。

当前配置每机会 fresh extraction、`output_cache=false`；这不是严格同身份 Solver 缓存漏命中或账本错误。重复 fresh draw 有探索和恢复价值，**6.23M 是重复请求的毛成本暴露，不是已证实可以无损省下的 Token**。它与失败 draw 成本有重叠，不能两项相加。复用只能研究完整必要上下文下的已接受诊断，失败输出不能缓存替代重试；新授权域、source、prompt、lane 或证据变化必须使兼容性重新验证。

### 8.4 后 23 次机会为何仍消耗却无 Commit

第 28–50 次花费 9,255,200 新 Token、3,839 请求，占续跑 Token 46.22%。产生 34 个合法编辑、31 个导出候选、14 个 Full，**14 个 Full Vote 全部为负，12 个目标净增为负、2 个为正**；累计 45 次 Vote 丢失，16 次独有新增、11 次独有丢失。平台期不是只有格式错误或 NO_SAFE，而是仍在得到可评估、完整表现不合格的候选。

整个过程实际在六个已部署团队状态上搜索（初始加五次 Commit），后 23 次都以同一个终态团队为父状态。它已经发生真正的 sequential evolution，但晚期 fresh Gradient 与全新 Pattern 身份仍不断从相同成员行为重新诊断；既有 Full 失败未稳定转化为下一次生成约束，是优先检验的学习闭环问题。

Reflection 契约无效由前 27 次的 12/162 个槽增至后 23 次的 22/138，NO_SAFE 从 108/162 降为 82/138。14 个完整渲染 prompt 超限均在第 27 次之后、目标为成员 5，其父 prompt 已为 2492/3000 字符；拒绝内容长 3048–3232 字符，一些收到反馈后仍重复超限。没有 Reflection 截断证据。明确剩余预算、允许受条件约束的重写是可研究方向，不是直接放宽总 cap 或删规则。

成员 1、4 的父 prompt 始终短，却仍大量 NO_SAFE，所以长度压力不能解释它们的主要困难。50 次资源上限时已完成三轮无 Commit，冻结科学停止需四轮；停止规则没有异常。不能依据后 23 次无效益就宣称科学收敛，继续花费也不能证明找到新候选的概率为零。

## 9. 下一轮设计优先级与最小机制验证

以下全为建议，未实现、未冻结、未执行，不授予 API 权限。任何改变抽样、指标、Memory、诊断复用、parent-survival、格式契约或 WHO 的研究都需新版本/身份和预算；不能回填现有结果。

| 排名 | 方向 | 预期科研价值 | 当前证据充分性 | 实现复杂度 | Token 成本判断 |
|---|---|---|---|---|---|
| 1 | 团队关键保留证据 + Vote 风险反馈 | 很高，直接面向有效团队变化 | 信息/覆盖不足强；干预效益未测 | 中 | 先零 API 面板目录诊断；加两锚题约 0.25M Solver 增量，优化器输入另计 |
| 2 | Full Memory 保证送达、明确失败 scope | 很高，复用已经付费获得的失败证据 | 实际 wire 丢弃强；行为影响未测 | 中 | 先离线，八机会配对约 3.2M 加 bootstrap |
| 3 | Solver 稳定性 + 条件 additive repair 正对照 | 很高，分开 mutation 质量、能力与波动 | 可见数学错误强；竞争解释未识别 | 中 | 480 + 120 逻辑评估粗估约 0.59M，恢复/初始化另计 |
| 4 | Gradient 格式与语义质量联合改进 | 高，提高有效证据而非空格式 | 序列化问题强；诊断正确性需人工评定 | 低–中 | 离线表示测试；100 对 ×两变体约 1.4M，另冻结上限 |
| 5 | 完整上下文 accepted diagnosis 复用与稳定机制身份 | 费用价值高，科研价值依赖保留探索 | 重复量强；潜在探索损失未知 | 中–高 | 毛重复暴露 6.23M，不能当保证节省 |
| 6 | 阶段/成本感知 WHO | 中–高，需要同父状态比较 | 无规则错误/饥饿；缺反事实质量 | 中–高 | 五成员一个共同父约 2M，两个父约 4M 加 bootstrap |
| 7 | 受条件约束重写、诊断细节与弃权可观察性 | 中，可减少局部晚期摩擦 | 长度摩擦强；宽 Pattern/弃权原因未识别 | 低–中 | 先离线核验预算与信息，再小配对；不能牺牲角色信息充分性 |

成本仅按续跑观测均值作量级估算：Solver 每物理请求约 978 Token，Gradient 约 4634 Token，每机会均值约 0.40M。不是上限承诺，逻辑评估和物理恢复调用不同；未来必须单独冻结预算、源、phase、缓存身份和授权。研究设计的完整机器可读内容见 `minimal_studies.json`。

**方向 1 的最小离线验证：** 在固定 31 个 Full 候选目录上，用父状态已有 margin/唯一正确等特征构造均匀与风险分层面板，比较危害检测与可用候选排名；不利用待判断 child Full 标签去挑题，按机会/父状态分组评估。该目录经过晋级选择，最多验证局部代理在这些已见候选上的信息价值，不能声称提升 optimizer。随后固定父状态做 2×2：原面板/增加两条完整保留锚点 ×目标指标/团队 Vote 风险反馈，其他角色输入与外层门禁一致，区分覆盖与指标。既有 Mutation 三题完整保留。若原计账为 root 六题加六代各六题（42），增加两题后需明确改为 56；不能悄悄扩大冻结预算。只在已有题上增加 peer-aware 评价可以复用固定 peer 输出，少增加 Solver，但无法弥补没看到关键题。

**方向 2 的最小验证：** 先只重放 retrieval，检查相关 Full 记录能否按显式 scope 保留下来，不运行优化器。再以两个父状态、两个目标成员、两种送达策略构成八机会配对；优先级和容量要分别比较，不把两个改动混成一个原因。保留完整数学证据，送达内容应标注来源、适用范围、Vote 风险和失败类型。观察实际 wire、反复 critical loss 和每 Token 的有用 Full 候选，而不是 bank size。

**方向 3 的最小验证：** 四个冻结 parent/child 对，预注册每对二十道 Optimize 题（修复、关键保留、独有覆盖、未受影响对照），两 prompt 各三个独立 realization，共 480 逻辑评估；另两条人工条件修复 prompt 在同二十题各三次，增加 120。新的采样身份和缓存政策必须保证独立 draw，first-valid 恢复不能变成 retry-until-correct。人工正对照用于判断 P2 式 additive repair 是否能在此 Solver 上稳定实现；不是为了重跑不利正式实验取得更好成绩，不读取 held-out 来调方法。

**方向 4–7：** 严格保持参考与普通轨迹，先测试数学符号/JSON 字节忠实性；live 格式干预同时盲评 diagnosis 的正确性与可实现性，避免“更短、更合格式、更无用”。复用诊断只接受完整兼容上下文和正确 provenance，不能牺牲 peer 信息来提高命中率。WHO 先做同父状态五个成员的等预算机会比较再谈收益调度。prompt 长度和广义 Pattern 应各做条件 rewrite/诊断信息保留干预，NO_SAFE 原因字段只能帮助观察、不能证明真正原因。

## 10. 已排除、仍未知，以及不应直接采取的捷径

目前未见 V2.7 gate 实现错误、责任选择偏离代码、top-4 丢弃已知局部正收益或同一局部子集与 Full 使用不同实现。没有证据支持以降低 Full Vote 保留要求来换 Commit。

真正未识别的是：安全弃权背后的具体原因、完整诊断与广义 Pattern 的数学质量、追加式文字如何改变 Solver 行为、不同 prompt 间 realization 波动大小、未晋级候选的 Full 质量，以及未选成员同父状态的产出。以上均不能用汇总图或更长的一次正式运行替代对照。

不应直接增加 generation、强制所有成员更新、收紧局部正增门禁、放松 JSON/Full 守卫、首个 NO_SAFE 就停止，或删掉数学证据/改回数字切片。已有数据分别显示未知收益、关键能力风险、会错失赢家、掩盖失败或损失成功机会。独立 Validation 对未来泛化结论必要，但不是此处机制识别的替代，也没有在本任务中启动。

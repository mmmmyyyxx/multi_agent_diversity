# After architecture

The new opt-in method enters `run_experiment` with `SearchMethodConfig` and
dispatches to one `UnifiedSearchOrchestrator`. The orchestrator takes explicit
benchmark, aggregation, state, diagnosis, opportunity, search engine,
evaluation, transition, gate, commit, history, memory, and stop ports.

Current BBH composition uses raw overlapping responsibility, feasibility
before target ranking, immutable role-based Optimize evidence, a GEPA-derived
search bridge, progressive team evaluation, Common-Safe, winner-only Shadow,
and atomic system write-back. The compatibility boundary translates the new
opportunity into the pinned low-level BBH evaluator and GEPA packet types. It
does not invoke the historical TeamSearchController or historical task builder.

`GEPADerivedConfig` has its own scientific identity and may change under a new
version. The pinned official GEPA baseline keeps its exact configuration and
historical Formal V3 replay path. Pattern analysis and LLM memory are null by
default; LLM aggregation is implemented but responsibility under that
aggregation remains blocked pending a separate scientific decision.

The governed CLI continues to reject a new unified real-API manifest until a
future frozen execution adapter, manifest, and explicit authorization exist.
This does not affect zero-API composition tests through `run_experiment`.

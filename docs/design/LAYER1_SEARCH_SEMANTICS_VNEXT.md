## Boundary and identity

`LAYER1_RESPONSIBILITY_CONDITIONED_SEARCH_V1` replaces the local official GEPA
loop only in a new opt-in MATH execution binding. `OFFICIAL_GEPA_FIDELITY=NO`.
The high-level method remains Unified Team Prompt Search V2.1. Historical
bindings retain official GEPA, their candidate guards and request/cache policies.

Layer2 still selects the target using V=max(4D,2N,C)/(1+f), builds Optimize-only
role-bearing evidence, evaluates candidates with fixed peers, promotes at most
two, enforces the immutable initial competence floor and strict team gain,
checks only the Full-safe winner on Shadow, and commits one member atomically.
The local backend cannot read the Shadow capability, Validation or Test,
reselect the target, alter peers or authorize deployment. Pattern chooses WHAT
after WHO; when enabled it remains one focus. Memory remains a separate port.

## Inputs and feedback state

Inputs are the selected parent decision procedure, target slot, D/N/C/V and
discounted target objective, Optimize mutation and local validation evidence,
legal repair/preservation/boundary roles, optional focused Pattern and Memory
context, and a fixed budget. The backend checks every evidence source before
materializing a local task. No other data loader is supplied.

An immutable local evaluation panel contains at most six unique Optimize
examples, interleaving repair and preservation/boundary evidence. Every compared
procedure uses that same panel. The root is evaluated once. Records contain
problem, legally available reference, parsed prediction, correctness, validity
and invalid reason, role/lane, and structured evaluator feedback. Visible Solver
reasoning is optional and unnecessary. The schema is SolverObservation, not
Reasoning Evidence. Generation also sees target objective, the complete parent,
hash-bound archive diagnostics, and recent candidate outcomes. Different failure
packets or responsibility contexts therefore change the actual generation input.

## Proposal and local loop

Each opportunity starts an empty archive and fresh generation state. At most
six physical successful non-Solver generations are requested, with the frozen
transport retry policy accounted separately. Each generation requests a complete
procedure as a single JSON object containing `decision_procedure` and no other
key. This is the optimizer response envelope, not a Solver interface mutation.
The proposer receives the semantic boundary and rejected-contract feedback.
No candidate is repaired, silently truncated or regenerated outside this bound.

Each changed, unique, contract-valid proposal receives a complete panel
evaluation if it fits the remaining 36 logical Solver metric calls. Contract
rejects and duplicates consume generation budget but no Solver metrics. The
next parent is the best observed local procedure including the root, with stable
ties. Locally negative proposals remain in the archive and inform subsequent
generation; strict improvement is guidance for parent choice, never admission.
No official Pareto/frontier survival or perfect-score skip is required.

## Candidate contract and pool

`SEMANTIC_MUTABLE_REASONING_CONTRACT_V2` rejects empty/over-3000 text,
normalization-equivalent parent no-ops, external Solver interface mutation,
fixed answer payloads, and verbatim supplied-example copying. It permits benign
final-answer reasoning, mathematical representation reasoning, and changed
append-only procedures. Append-only is observed as a mutation shape.
External presentation controls remain forbidden: literal parser markers,
line counts/placement, response-only directives, Markdown/code-fence or JSON/XML
Solver schemas. Mathematical forms, exactness, units, domains, simplification,
equivalent expressions and substitution checks are reasoning choices.

All changed admissible unique evaluated proposals enter the pool before export
ranking. At most four are returned, ordered by local newly-fixed count,
preservation of root-correct examples, correct count, then stable generation.
This bounded ranking can reduce the pool but cannot prune solely on local
rejection or lack of frontier membership. Textual diversity is not an objective.
Candidate records carry parent/prompt/evidence hashes, target, generation and
source call, panel IDs/scores/delta/fixed/broken/invalid counts, mutation shape,
local sign/status and export reason. Layer2 never uses local scores to deploy.

## Bounds, stopping and caching

The loop stops at six generations, insufficient room for a complete next panel,
or the end of the bounded loop. Its resource termination is not team convergence.
There are at most 36 logical local Solver metrics, four exports and two Full
promotions. The global team_epoch_no_commit_v1 stopper remains unchanged and
never schedules members round-robin.

`SOLVER_MEMBER_LANE_EXACT_CACHE_V2` permits resolved Solver reuse only. Scientific
identity includes the attempt/namespace, member realization lane, prompt,
sample, model, generation policy and immutable benchmark interface. The same
member/request can reuse across initial/local/TeamMiniBatch/Full, and Initial vs
Final Validation. Different slots never share stochastic realizations.
Reflection/Pattern and future generative roles make fresh draws. No output
crosses scientific attempts, including Canary to Pilot.

The new generation policies freeze Solver temperature0.2 with the other V1
fields unchanged, and non-Solver temperature0.7/top_p0.8/top_k20,
presence_penalty1.5/frequency_penalty0/thinking=false. Solver cap3600 and
optimizer requested completion cap1800 (accounting ceiling1810) remain.
Solver recovery remains one initial plus at most three identical-request
semantic retries. Retry response diversity is observation only.

After search closes, ordered deployed mutable prompt hashes determine changed
members. An unchanged team produces SKIPPED_NO_TEAM_CHANGE, zero Validation
calls, NOT_ESTIMATED signal and NO_INTERVENTION outcome; no bootstrap or numeric
paired delta is fabricated. A changed team receives the frozen post-search
Validation100 comparison. Validation cannot restart search. Test remains sealed.

## Official GEPA disposition

Retained conceptually: reflective proposal generation, bounded metric evaluation,
candidate archive, parent/candidate lineage, local feedback and evidence roles.
Removed in this binding: official optimize(), strict-local survivor admission,
Pareto instance frontier, official parent selector, official reflective schema,
perfect-score skipping and accepted-only full validation. Modified: deterministic
panel scheduling, observation records, archive-based parent choice, and export
ranking after whole-pool admission. None is claimed as exact official GEPA.

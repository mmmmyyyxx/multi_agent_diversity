# V2.5 bounded generated-output recovery

This amendment is normative for `unified_team_prompt_search_v2_5_generation_recovery_v1`.
It supersedes generated-content failure handling and the literal-only symbolic
overlap decision in the V2.5 contract. All other scientific rules remain binding.
Flexible answer extraction V3 and pinned equivalence remain current. Historical
scores, contracts, manifests and reports are immutable.

## Source-aware abstraction

The content guard reads Optimize input, gold, target output and reference solution.
Gold copying, explicit fixed-answer intent, entities, labels, long source fragments,
unique constant-bearing expressions and numeric provenance remain rejection signals.
Short symbolic overlap alone is ambiguous. A bounded elementary expression grammar
admits a general-method overlap only with explicit generic context, symbolic
parameters or a nontrivial identity, and no instance or answer cue. Small coefficients
alone never establish genericity. Copied equations fixed to a numeric total other
than zero or one remain case-specific, even with a genericity claim. No incident
expression is whitelisted.
This is a conservative provenance rule, not a semantic proof. Unsupported formulas
can still be rejected; rejected content never enters Pattern, Layer1 or Memory.
Private audits retain source field, span hash and decision. Public evidence is sanitized.

## Closed local recovery

Only typed, post-response `GeneratedOutputFailure` errors in a closed stage category
can recover. An identically worded untyped error remains fatal. Each physical response
is durably receipted and charged before content checks; rejected responses are not
cached as valid outputs. Sampling, transport retries and output capacities are unchanged.

Null ordinary content with valid provider evidence is a rejected output, not an
accounting fault. Missing response fields, invalid usage or metadata contradictions
remain fatal. Gradient has at most three draws per wrong example, covering syntax, schema, content
and truncation. A valid UNCERTAIN stops immediately. Exhaustion yields
NONACTIONABLE_EXHAUSTED while preserving other legal gradients. All nonactionable
examples produce a legitimate NO_ACTIONABLE_PATTERN opportunity.
Cluster has at most three whole-response syntax/truncation draws. Membership validation
precedes content validation. Unknown, duplicate, conflicting or out-of-universe IDs
remain fatal. Invalid content with known legal supports drops that pattern only and
moves exactly its supports to unassigned. Other patterns survive; no semantic assignment
is invented. All discarded patterns may yield a legal empty partition.
Layer1 retains its six total generations, 42 metric evaluations and four exports.
Truncated Reflection or malformed edit consumes a generation, retains previous legal
candidates, and continues within the bound. No generation increases output capacity.
Provider, identity, authorization, ledger, cache, checkpoint, split-access, receipt,
provenance and unknown errors never become generation recovery.

Mutation3, independent SearchValidation3 and disjoint TeamProbe6; two Full promotions;
assigned repair 0-to-1; capability floor, Vote, Shadow and commit thresholds are unchanged.
No efficacy-based retry or Canary-to-Pilot gate is permitted.

## Lifecycle and frozen execution

Initial state is persisted before owner review. A compute-return milestone is private
evidence only and does not authorize replay or resume. Resource closure, summary and
accounting readback, inventory hash verification and closure receipt precede the terminal
completion marker. Terminal inventory excludes its own inventory, lifecycle and closure
receipts to avoid hash cycles; the terminal marker binds the inventory and receipt hashes.
Persistence failure is fatal. This repairs known ordering windows, not the undetermined
historical process-disappearance root cause.

New seed-84 Canary and Pilot start independently with the registered five identical
Arm B prompts and five bootstrap Memory entries. They freeze independent attempts,
cache namespaces, manifests, receipts, ledgers and roots. No prior responses or learned
state transfer. Both development memberships freeze before either outcome: unseen-first
metadata stratification, with the minimum prior-use supplement only when the existing
frozen development pool is insufficient. Membership overlap and provenance are disclosed.
No new split or held-out raw access is allowed. Canary Optimize12/Shadow40/one opportunity
and Pilot Optimize60/Shadow40/up to five opportunities each bind a 2,000,000 charged plus
reserved token ceiling, combined at most 4,000,000. Four Solver semantic draws and all
existing generation caps remain unchanged. Real API authorization requires both exact
post-freeze scopes; one approval covers engineering-gated Canary then Pilot, no reruns.
Validation and Test remain unauthorized. Local commits only; no push authorization.

# Opt-in cross-member rolling risk memory V4

`structured_cross_member_rolling_risk_memory_v4` extends the bounded V3
action memory. It is a separate scientific identity. V3 and its completed
execution binding remain unchanged. No real execution is authorized by this
offline amendment; a future run requires a new binding, manifest and handoff.

The signature `closed_action_outcome_failure_signature_v1` uses the existing
grounded, closed Add/Remove/Revise action concepts, measured preservation-loss
class and repair-gain/loss pattern. Different wording can match; equal hashes
or deltas cannot establish a family. Recognized Responsibility lanes are
applicability metadata, not a reason to split equivalent mechanisms. Unchanged,
contract-invalid, unevaluated, operational and unclassified edits cannot
support promotion. Categories describe observed associations, not proved causes.
Zero local Solver invalid responses must be explicitly observed: procedure
conformance alone does not establish parser/response validity. Missing validity
counts, terminal parser failures or duplicated/operational outcomes cannot
support a repeated-private reasoning family. Existing direct structural-source
categories retain their original separate admission contract.

Immediate negative feedback stays private. At a completed opportunity's memory
transaction, a family supported by at least two distinct members in the recent
48 completed-opportunity window may become one shared entry. Same-member
recurrence strengthens private relevance only. Direct, measured TeamProbe,
Common-Safe and aggregate Shadow rejections remain shared sources. A direct
source with the same closed signature can merge with promoted private evidence;
origin is TEAM_STRUCTURAL_REJECTION, REPEATED_PRIVATE_FAILURE or MIXED.

Shared text contains a generic risk category, closed mechanism concepts and a
compressed safeguard. It excludes another member's procedure, strategy text,
sample IDs, questions, answers and provider summaries. Internal observation IDs
deduplicate evidence; they do not define semantic equivalence. Lifetime occurrence
counts refer to observations across local and structural stages while an entry
is retained, not unique candidates. Metadata includes member count, lanes,
severity category and last seen. A consumed-observation acknowledgement prevents
bounded shared history from recounting old private evidence.

`recent_opportunity_recurrence_retention_v1` uses recent recurrence, recent
distinct members, current lane, last seen and stable semantic key, in that order.
Entries with no evidence inside the 48-opportunity window expire. Lifetime
frequency never confers permanent retention. Shared storage remains 48; each
entry holds at most 48 generic observations; the separate recent failure evidence
bank holds at most 240 (five times the shared limit). These derived bounds are
explicit configuration identity, not hidden defaults. Storage selection differs
from retrieval: same lane, compatible family, last seen, recent recurrence, key.
Retrieval remains top-k 3 shared and 3 private successes; the existing at-most-five
private failure queue has priority, with the complete canonical view capped at
1200 characters by dropping whole lowest-priority entries. Private failures
remain 5/member and successes 24/member. Private and shared eviction are independent.

Prepare is atomic, apply validates revision and bounds, and completed-opportunity
clock updates invalidate stale deltas. Incomplete/operational outcomes cannot
promote. Memory starts empty per attempt, reads only after WHO selection, and
makes no provider calls. Validation/Test cannot read or write it. Shadow sample
material is never consulted. Responsibility, feasibility, Layer1 anchor,
36 metrics, six generation bound, four exports, parent update, candidate
contract, Layer2, models, generation, split, team and evaluator are unchanged.

Required telemetry: current failure families/repeated families, promotions,
shared created/updated/evicted, peak/final storage and reads, plus each retained
promoted family's occurrence/member counts, origin, category, lanes and last seen.
Eviction counts count previously stored families; rejected incoming entries are
not misreported as prior stored-entry evictions. Family counters are recent-bank
gauges; creation/promotion/eviction counters accumulate within one attempt.

# Bounded Gradient contract recovery V1

`PER_EXAMPLE_GRADIENT_CONTRACT_RECOVERY_V1` is an explicit sampling amendment.
Each selected-member wrong Optimize example still contributes exactly one
accepted hypothetical corrective Gradient. At most three successfully generated
physical draws are allowed. Accept the first output satisfying the unchanged
Gradient V1 schema, hard400, structural/interface checks and Guard V6. A valid
weak or generic instruction is accepted immediately, with no quality selection.

Each draw uses identical provider-visible request bytes: Prompt V3, member
procedure, example, model, decoding, role and split remain frozen. Previous
outputs, rejection reasons and extra repair instructions never enter the request.
There is no output cache, judge, best-of-N ranking or Gradient ensemble.

Only deterministic generated-output violations permit another draw. Input,
wrong-universe, duplicate identity, held-out access, context, provider binding,
budget/accounting, transport exhaustion, persistence and arbitrary code failures
propagate. Transport attempts retain their independent existing policy. Three
invalid outputs stop with `PATTERN_GRADIENT_EXTRACTION_INVALID`; no example is
dropped, fabricated, passed to clustering without a valid Gradient or assigned
unassigned as a substitute for extraction.

Every physical draw is durably audited before acceptance or another draw, with
logical identity, draw number, response/Gradient hashes, validity/category,
length, Guard V6 reasons and tokens. Accepted draw and prior-invalid counts are
recorded separately. Raw responses retain the existing pre-charge sealed receipt.
Only accepted records enter clustering; telemetry has no ranking or score role.

Gradient ceilings multiply by three. Accepted Gradient universe, clustering,
Partition Completion V1, WHO/same-F, representatives, Memory, Layer1, team gates,
Solver/reflection budgets, opportunities and scientific stopping remain frozen.
The cumulative durable40M journal remains authoritative. Gross reservation
bounds include released reservations and are not spending guarantees.

Historical bindings without this opt-in retain single-draw behavior. The prior
Guard V6 task's strong-leakage dispatch boundary remains intact in its receipt;
only the new validated recovery authority permits a fresh attempt. Each real
attempt requires a new source/binding/cache namespace and exact single-use grant
under the new user task. Valid negative outcomes, including zero commits, do not
permit another scientific run. Operational retries require strict invalidity.

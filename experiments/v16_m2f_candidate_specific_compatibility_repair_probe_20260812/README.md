# M2F Candidate-Specific Compatibility Repair Probe

This sanitized report covers seven frozen historical M20 candidates that each
repaired assigned responsibility evidence while causing target-member
regression. Each candidate received exactly one post-hoc compatibility-repair
generation using its actual train-side gains and losses, followed by the same
fixed-parent evaluator and common-safe policy. No prompt was committed and no
validation or test data was used.

The protocol gate passed all seven cells. M2F retained all 13 source
responsibility repairs and added two different responsibility repairs. Total
non-responsibility loss fell from 77 to 72, with candidate-level collateral
directions of 4 wins, 1 tie, and 2 losses. Three formerly infeasible source
candidates became common-safe feasible.

The frozen classifier is `PIVOTAL_COMPATIBILITY_FAILED`, not `REPAIR_WORKS`.
Pivotal losses increased from 10 to 13 despite the aggregate collateral
reduction. The result therefore indicates that candidate-specific loss feedback
can preserve targeting and rescue some candidates, but critical competence
retention remains unresolved. M2F is not authorized for a training pilot or
canonical promotion.

This is seven-candidate mechanism evidence only. No significance or
population-level efficacy claim is made. Runtime prompts, questions, answers,
raw responses, caches, endpoints, credentials, and absolute paths are excluded.
